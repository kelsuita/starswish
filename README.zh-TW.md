# 星願攢錢

[English](README.md) · [简体中文](README.zh-CN.md) · **繁體中文** · [日本語](README.ja.md)

> 把想買的東西寫下來，看著它一點點變成現實。

一個用 Kotlin + Jetpack Compose 寫的 Android 存錢目標應用程式。介面基於 **MIUIX 0.9.4**，參考了 HyperOS 的設定頁與大標題互動：整頁橫向切換、上滑折疊標題、跟隨強調色推導的完整色板，以及可選的背景模糊。

[下載安裝](https://github.com/kelsuita/starswish/releases/latest) · [回報問題](https://github.com/kelsuita/starswish/issues) · [愛發電贊助](https://afdian.com/a/kelsuita)

## 簡介

星願攢錢不碰你的錢，只做一件事：把「想存多少、還差多少、每天大概要存多少」算清楚，擺在每天都會看到的地方。

你可以同時維護多個存錢目標，把每個目標的進度綁定到一個或多個儲蓄帳戶。首頁橫幅會展示你指定的那個目標，進度條、百分比和每日建議金額都隨帳戶餘額即時更新。金額全部用整數分計算，不會出現 `0.1 + 0.2` 那種誤差。

如果你也在用小星記帳，可以在你主動開啟帳戶詳情頁時，由應用程式讀取頁面上可見的「人民幣餘額」，核對後再同步到目標裡——沒有背景同步，不會讀帳單流水，也不會替你確認。

## 快速開始

1. 下載並安裝與你裝置架構匹配的 Release APK，不確定時選擇 `app-universal-release.apk`。
2. 在「帳戶」新增帳戶並填寫餘額；不使用小星記帳時，也可以完全手動維護。
3. 在「首頁」建立心願，填寫目標金額、關聯帳戶並選擇進度計算方式。
4. 更新帳戶餘額後查看目標進度。主題、強調色和首頁橫幅可在「設定 → 主題設定」調整。

小星記帳餘額讀取為可選功能，需要單獨啟用無障礙服務；首次使用請閱讀下方的接入說明。

## 功能

### 存錢目標

- 設定目標名稱、目標金額與可選截止日期；首頁橫幅、進度條與圖示跟隨應用程式強調色
- 每個目標可綁定一個或多個儲蓄帳戶，展示進度百分比、已存金額、剩餘金額與每日建議金額
- 兩種進度演算法：按帳戶**目前餘額**計算，或從建立目標時的餘額**起點**計算新增累積
- 進度限制在 0%–100%，多目標餘額不會相加，也不會互相佔用

### 儲蓄帳戶

- 手動新增、修改、刪除帳戶；仍有關聯目標的帳戶會被阻止刪除
- 支援從小星記帳讀取目前餘額：在你主動發起請求後，開啟小星帳戶詳情頁即自動辨識金額，回到星願核對後確認同步
- 讀取只針對單個帳戶、單次請求，兩分鐘內未完成或頁面資訊不明確就停止

### 主題與外觀

外觀選項包括：

- 主題模式：跟隨系統 / 淺色 / 深色
- 深色模式純黑背景：僅深色模式生效，頁面底色轉為純黑，卡片保留層次
- 強調色：預設、莫奈取色、藍色、綠色、橙色、紫色
- 調色板風格與 Material 3 色彩規範（2021 / 2025），由 MIUIX `ThemeController` 推導完整色板；莫奈取色時同樣生效
- 首頁橫幅：淺色 / 深色；可指定橫幅展示哪個目標；緊湊目標清單
- 背景模糊：Android 13 及以上可用，作用於大標題列與底部導覽
- 語言：跟隨系統 / 简体中文 / 繁體中文 / English，在設定頁頂端即時切換，無需重新啟動；首次啟動預設跟隨系統

背景模糊開關位於「設定 → 外觀」，其餘上述選項集中在主題設定頁。設定儲存在本機，重新啟動後依然生效。

### 互動與細節

- 首頁、帳戶、設定三頁整頁橫向切換，標題與內容一起跟手移動，底部導覽固定；各頁保留獨立捲動位置
- 頂部大標題隨捲動折疊，清單捲動到邊界時有回彈效果
- 首頁橫幅、目標卡片與帳戶卡片按 Miuix 字級體系重新排版；應用程式圖示為漸層底 + 星形主體的自適應圖示，含 Android 13 單色層
- 「關於」是獨立頁面，包含專案 GitHub、愛發電贊助入口、使用步驟、資料與權限說明、進度計算方式和官方介面文件
- 設定頁頂端的一言僅在簡體或繁體中文介面且已啟用時顯示：首次使用中文介面預設開啟，可在「設定 → 外觀 → 主題設定 → 首頁」關閉；非中文介面自動隱藏並停止請求，切回中文保留先前的開關選擇。啟用且沒有本機一言時從公開介面取得並儲存，切頁或重新啟動不會重新整理已有內容，點擊可手動重新取得

### JSON 備份

- 入口位於「設定 → 備份 → 匯入與匯出」，在外觀分組下方、應用程式分組上方
- 匯出帳戶、目標、外觀設定和已儲存的一言，透過系統檔案選擇器儲存為 JSON
- 匯入時校驗備份格式、版本、金額範圍及帳戶關聯，確認後整份取代現有資料；建議先匯出目前資料
- 備份為明文檔案，包含帳戶名稱與餘額，請妥善保存；支援最大 1 MB 的備份檔案
- 不包含讀取中的臨時請求、待確認餘額或系統無障礙權限；換裝置後需重新啟用權限

## 隱私與資料

- 所有目標與帳戶資料僅儲存在本機私有儲存空間，無帳號、無登入、無廣告、無統計 SDK
- 不讀取銀行卡號、密碼或完整帳單，不執行點擊、轉帳或修改小星記帳資料
- 僅在中文介面啟用一言且需要取得內容或手動點擊重新整理時發出請求；非中文介面或關閉開關時不請求，不會向該介面傳送帳戶、餘額或目標資訊；開啟 GitHub、贊助或官方文件連結時會跳轉外部應用程式，由對應網站處理存取
- 小星餘額讀取依賴 Android 無障礙服務，只辨識限定的應用程式套件名稱與帳戶詳情頁，可隨時在系統設定中關閉
- Android 系統自動備份與裝置移轉已關閉；可手動匯出 JSON 備份。解除安裝應用程式會刪除本機資料，請提前將備份保存到應用程式外部

## 小星記帳接入方式和邊界

已核對的官方文件：

- URL Scheme：<https://cxincx.com/support/scheme.html>
- 加密備份說明：<https://cxincx.com/support/backup/7.html>

根據專案接入時核對的文件，Scheme 提供插入帳單與喚起自動記帳彈窗，未提供本專案可用的帳戶餘額查詢介面，備份檔案也不能直接開啟讀取。因此，目前實作透過可見頁面辨識餘額，不解析加密資料庫，也不使用帳單流水累計值代替餘額。

目前使用 Android 無障礙服務讀取使用者主動開啟的 **小星記帳可見帳戶詳情頁**：

1. 在「帳戶」新增儲蓄帳戶，名稱必須與小星記帳完全一致，並填寫初始餘額。
2. 閱讀應用程式內說明，再到系統設定開啟「星願攢錢 · 讀取小星帳戶」。
3. 在帳戶卡片點擊「讀取小星餘額」，應用程式會開啟小星記帳。
4. 兩分鐘內開啟對應帳戶詳情。服務偵測到 `com.cxincx.xxjz.account.AccountDetailActivity` 後自動讀取頁面，要求完整帳戶名稱與頂部「人民幣餘額」及數值可見；忽略下方流水裡的歷史餘額。無需在小星頁面額外點擊讀取。
5. 成功讀取後，小星頁面頂部顯示「已讀取，請返回星願」膠囊，點按直接開啟星願的「帳戶」確認頁；核對辨識金額後點擊「確認同步」。膠囊顯示 3 秒後自動淡出，也可手動返回星願查看待確認結果。

頂部膠囊是流體雲風格的本機無障礙懸浮提示，不是 OPPO 系統原生流體雲。它使用已啟用服務的 `TYPE_ACCESSIBILITY_OVERLAY`，不另索取一般懸浮視窗權限，不顯示帳戶名稱或餘額，也不會自動確認同步。原生 OPPO 流體雲仍需平台服務授權、UPK 範本及 SeedlingSupportSDK 接入，目前未接入。服務中斷或銷毀時會移除膠囊；點擊支援星願冷啟動及已在背景執行的兩種情況。提示僅在成功辨識並儲存候選餘額後出現，不能取代真實裝置讀取聯調。

**這不是背景即時同步**。一次請求只針對一個帳戶，收到候選結果或兩分鐘逾時後停止讀取。沒有明確名稱、餘額標籤、有多個不同餘額、信用額度、外幣、總資產總覽等情況下會拒絕辨識；手動更新始終可用。未讀到時可直接返回修改餘額，或重新發起讀取。授權未開啟時不會發起讀取。

已依據使用者提供的 Activity 名稱與帳戶詳情截圖適配頂部人民幣餘額，並新增包含流水歷史餘額、金額分離節點的解析測試。尚未取得真實裝置的無障礙節點聯調結果；部分頁面可能不暴露可存取文字或使用不同標籤。**截圖和解析測試不能取代真實小星版本的讀取驗證。**

頁面讀取僅限定小星套件名稱 `com.cxincx.xxjz`；不執行點擊、修改帳單、轉帳，不儲存截圖和完整頁面文字。僅在中文介面啟用一言且需要取得內容或手動重新整理時向 `v1.hitokoto.cn` 發起請求，不向該介面傳送帳戶、餘額或目標；非中文介面或關閉開關時不請求。應用程式有 INTERNET 權限，備份與裝置移轉關閉。可隨時從系統設定關閉服務。解除安裝會刪除應用程式資料。

Android 13 及以上從檔案安裝應用程式時，系統可能先限制開啟無障礙權限；如出現此情況，可在本應用程式的系統「應用程式資訊」選單中按系統提示允許受限設定，再手動開啟。權限必須由裝置使用者確認。

## 建置與安裝

要求 JDK 21、Android SDK Platform 37、可用網路或已有依賴快取。Gradle Wrapper 已包含。最低支援 Android 8.0（API 26），targetSdk 36。

Windows（執行單元測試、建置 debug APK 並執行靜態檢查）：

```powershell
powershell -ExecutionPolicy Bypass -File tools\build.ps1
```

或者在 Android Studio 開啟本目錄，同步 Gradle 後執行。Android Studio 可自動建立本機 `local.properties`；該檔案不應提交到版本控制。

也可以直接執行 Gradle 任務：

```powershell
./gradlew.bat testDebugUnitTest assembleDebug lintDebug
```

產生的 debug 安裝包：`app/build/outputs/apk/debug/app-debug.apk`。

```powershell
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

### 正式簽章與 release 建置

發布的 release APK 使用專案專用正式金鑰簽章，不會回退到 Android 偵錯簽章。私鑰和包含密碼的本機設定不包含在儲存庫中。維護者在新環境建置正式版本時，需要從安全備份還原金鑰，並在專案根目錄建立 `keystore.properties`，檔案格式如下：

```properties
storeFile=C:/secure/path/starswish-release.keystore
storePassword=YOUR_STORE_PASSWORD
keyAlias=starswish
keyPassword=YOUR_KEY_PASSWORD
```

`keystore.properties` 已由 `.gitignore` 排除，金鑰檔案也不應提交或上傳到公開儲存庫。設定好後執行：

```powershell
./gradlew.bat assembleRelease
```

已簽章 APK 輸出到 `app/build/outputs/apk/release/app-universal-release.apk`。沒有本機簽章設定時，建置會輸出未簽章 APK，不能直接作為安裝包發布。自行建置分發時可使用自己的金鑰，但無法覆寫安裝本專案正式發布的 APK。

發布前可使用 Android SDK Build Tools 中的 `apksigner` 檢查簽章：

```powershell
apksigner verify --print-certs app/build/outputs/apk/release/app-universal-release.apk
```

請將 Build Tools 目錄加入 `PATH`，或使用該工具的完整路徑。維護專案正式版本時，應確認簽章憑證與既有正式版本一致，並為金鑰與密碼保留獨立的安全備份。

## 驗證

- `SavingsLogicTest`：金額精度與輸入邊界、綁定帳戶計算、從起點計算、負數/超額進度、餘額標籤、不同帳戶、歧義結果、信用額度及外幣拒絕。
- `lintDebug`：靜態檢查。保留固定依賴版本；版本升級建議和 KTX 風格建議不影響建置。
- 頂部膠囊已在隔離模擬器透過輔助無障礙服務載入實際建置中的提示元件，驗證顯示、自動消失、服務關閉時移除，以及點擊返回已執行的星願；確認頁冷啟動入口也已驗證。該元件測試沒有觸發真實小星的讀取事件，不代表實際帳戶餘額讀取已聯調通過。
- `tools/smoke-test.ps1`：安裝目前建置，在專用隔離模擬器驗證新增帳戶、目標必填校驗、進度計算、重新啟動持久化、權限揭露、關於頁與系統返回、邊緣返回手勢及主題設定。該腳本會清除指定測試模擬器中本應用程式的資料，不要對日常裝置執行。
- `tools/start-test-emulator.ps1`：使用本機已有 Android 35 x86_64 映像啟動隔離測試模擬器，連接埠 5580。不會操作連接的真實手機。測試腳本只會清空指定隔離模擬器中本應用程式的資料。

## 已知限制

- 小星記帳餘額讀取尚未在真實裝置上完成無障礙節點聯調，不同版本的頁面結構可能導致辨識失敗
- 已修正狀態列背景擷取範圍及切換標籤後底欄模糊失效的問題；已在 Android 35 模擬器使用宿主 GPU 驗證，其他廠商系統和 GPU 的表現仍需裝置驗證。詳見 [Miuix 審查記錄](docs/miuix-review.md)
- 僅支援人民幣儲蓄帳戶；不提供多幣別、自動轉帳或資金分配
- 正式 APK 目前為專案側載分發；尚未設定應用程式商店發布流程

### 語言包

所有介面文案都使用穩定識別碼（如 `home.current_wish`），實際文字放在
`app/src/main/assets/i18n/`（`en`、`zh-CN`、`zh-TW`、`ja`）。新增或修改翻譯只需改這些檔案，無需改動 Kotlin；
扁平的點號 key 可直接上傳到 Crowdin。缺少的 key 會回退到英文，再回退到識別碼本身。應用程式名稱與
無障礙服務名稱/描述也會在建置時從同一份語言包產生到 Android 資源，因為 Android 會在應用程式啟動前讀取它們。
新增一門語言時，把 `<語言代碼>.json`（可複製 `en.json`）放進同一目錄，再在 `Language.kt` 的
`AppLanguage` 末尾追加一項即可；資源目錄、跟隨系統匹配和語言序號範圍都會自動處理，且必須追加在末尾，
因為舊資料按列舉序號保存語言選擇。
